# Plan C.2 — Fix Reverse-Direction Import `sniffer/` ← `cli/`

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use `- [ ]` syntax.

**Goal:** Restore the layering rule "CLI sits above the protocol stack" by moving `SnifferSpec` out of `pybluehost/cli/_sniffer_arg.py` and into `pybluehost/sniffer/spec.py`. Today `pybluehost/sniffer/sink.py:54` reaches up into CLI for that dataclass — a clear architectural inversion.

**Architecture:** `SnifferSpec` is a pure dataclass + parser. It belongs to the sniffer subsystem. The CLI parses CLI args into this type — that's the only reason it currently lives in `cli/`, but the type itself has no CLI dependency.

**Tech Stack:** Pure Python module move + import rewrite. No new behaviour.

```python
def test_sniffer_spec_is_importable_from_sniffer_package():

def test_sniffer_spec_module_lives_under_sniffer():
    import pybluehost.sniffer.spec
    from pybluehost.sniffer.spec import SnifferSpec
    assert SnifferSpec.__module__ == "pybluehost.sniffer.spec"


def test_sniffer_module_does_not_import_cli():
    """Regression guard: pybluehost.sniffer.* must not import pybluehost.cli.*."""
    import importlib
    import pkgutil
    import pybluehost.sniffer as snmod

    for mod_info in pkgutil.walk_packages(snmod.__path__, prefix="pybluehost.sniffer."):
        m = importlib.import_module(mod_info.name)
        for attr in dir(m):
            v = getattr(m, attr, None)
            # If any module attribute is itself a pybluehost.cli.* module
            mod_name = getattr(v, "__module__", "") or getattr(v, "__name__", "")
            if isinstance(mod_name, str) and mod_name.startswith("pybluehost.cli"):
                raise AssertionError(
                    f"{mod_info.name} pulls in {mod_name}.{attr} — layering violation"
                )
```
