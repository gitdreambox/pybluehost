# PyBlueHost v1.1 Virtual Sniffer — Design Spec

**版本**：v1.1
**日期**：2026-05-29
**对应 PRD**：[docs/PRD-v1.1.md](../../PRD-v1.1.md)
**状态**：设计草案（待评审 → writing-plans）

---

## 0. 目标一句话

在 v1.0 Trace 系统上加一个新的 `TraceSink`，把 PyBlueHost 运行时的 live HCI 流（Command / Event / ACL / SCO）实时注入 Ellisys Bluetooth Analyzer 或 Teledyne LeCroy WPS 软件显示，借用它们的专业解码视图，无需空中抓包硬件。

---

## 1. 与现有代码的接点（已核对）

| 接点 | 现状（已读源码确认） |
|---|---|
| `TraceSink` Protocol | `pybluehost/core/trace.py:31` — `async on_trace(event)` / `async flush()` / `async close()` 三方法 |
| `TraceEvent` | `trace.py:19` — `timestamp / wall_clock(datetime,utc) / source_layer / direction(Direction) / raw_bytes / decoded / connection_handle / metadata` |
| `Direction` | `trace.py:14` — `DOWN = host→controller`（命令、host 发起的 ACL/SCO）；`UP = host←controller`（事件、controller 来的 ACL/SCO） |
| HCI `raw_bytes` 格式 | `controller.py:597 _emit_trace` 用 `command.to_bytes()` / 原始 transport data，**含 H4 packet type 首字节**（`packets.py`：0x01 cmd / 0x02 ACL / 0x03 SCO / 0x04 event / 0x05 ISO）。`source_layer="hci"` |
| sink 挂载 | `StackConfig.trace_sinks` list，`Stack._build(config=)` 前 append；`TraceSystem.add_sink` 也可运行时加 |
| CLI trace flag | `cli/_lifecycle.py:29 add_trace_arguments` 加 `--hci-log/--btsnoop`；`run_app_command(... btsnoop=, trace_spec=)`；sink 在 `Stack._build` 前 append 进 `config.trace_sinks` |
| 已验证 demo | `pybluehost/tools/Ellisys_live_virtual_sniffer.py`、`WirelessProtocolSuite_live_virtual_sniffer.py`、`test_live_virtual_sniffer.py` — 注入格式 + setup 序列已实测跑通 |
| Ellisys 注入类型常量 | `tools/bex400a_injection_api/Samples/Ellisys.Injection/InjectedHciPacketType.cs` — 见 §3.2 映射表 |
| WPS Drf personality | `tools/Live Import Developers Kit/liveimport.ini`：`Drf=Command;ACL;SCO;Event` → 位 0/1/2/3 = 1/2/4/8 |

**关键约束**：sink 的注入 payload **不含 H4 type 字节**（剥掉 `raw_bytes[0]`）；packet 方向/类型由各分析仪自己的字段表达。

## 2. 架构总览

```
HCI Controller ──emit──► TraceSystem (v1.0, asyncio queue + 单消费者 dispatch loop)
                            │  for sink in sinks: await sink.on_trace(event)
                            ▼
                   VirtualSnifferSink (NEW)
                     1. filter source_layer == "hci"
                     2. 拆 H4: h4_type = raw[0], payload = raw[1:]
                     3. 跳过空 payload / 不可表达类型
                     4. await backend.inject(h4_type, direction, payload, wall_clock)
                            │
              ┌─────────────┴──────────────┐
              ▼                            ▼
      EllisysBackend                 WpsBackend
       - encode_ellisys_packet()      - wps_frame_params()   ← 纯函数，可单测
         (纯函数，可单测)              - SendFrame3 via ctypes (run_in_executor)
       - UDP sendto (fire-and-forget) - InitializeLiveImportEx + SendNotification(start)
       - 启动 analyzer + PowerShell    - 启动 Fts.exe + connection string/config
         Ice: SelectDataSource +
         StartRecording
              │                            │
        UDP :24352                   ctypes call
              ▼                            ▼
      Ellisys.BluetoothAnalyzer.exe  Teledyne WPS Fts.exe
```

**分层原则**：
- **编码（纯函数）** 与 **传输/进程控制（Windows 副作用）** 分离。编码层跨平台、可单测；传输层 Windows-only。
- `VirtualSnifferSink` 不知道后端细节，只调 `SnifferBackend` 抽象。
- 两后端共享 H4→分析仪类型的方向语义，但映射值各自实现（见 §3）。

## 3. 包类型映射（核心逻辑）

输入：`(h4_type: int, direction: Direction, payload: bytes)`，`payload = raw_bytes[1:]`。

### 3.1 H4 type 常量（来自 `pybluehost/hci/packets.py`）

| 名称 | 值 | 典型方向 |
|---|---|---|
| `HCI_COMMAND_PACKET` | 0x01 | 永远 DOWN |
| `HCI_ACL_DATA_PACKET` | 0x02 | 双向 |
| `HCI_SCO_DATA_PACKET` | 0x03 | 双向 |
| `HCI_EVENT_PACKET` | 0x04 | 永远 UP |
| `HCI_ISO_DATA_PACKET` | 0x05 | 双向 |

### 3.2 Ellisys 映射（`InjectedHciPacketType.cs` 已确认）

ACL/SCO/ISO 的注入类型**取决于方向**（FromHost / FromController）：

| H4 type | Direction | Ellisys packet type |
|---|---|---|
| Command 0x01 | DOWN | `0x01` Command |
| Event 0x04 | UP | `0x84` Event |
| ACL 0x02 | DOWN | `0x02` AclFromHost |
| ACL 0x02 | UP | `0x82` AclFromController |
| SCO 0x03 | DOWN | `0x03` ScoFromHost |
| SCO 0x03 | UP | `0x83` ScoFromController |
| ISO 0x05 | DOWN | `0x05` IsoFromHost |
| ISO 0x05 | UP | `0x85` IsoFromController |

### 3.3 WPS 映射（Drf 位域 + Stream）

Drf 来自 personality `Command;ACL;SCO;Event` = 位 0/1/2/3；Stream：`STREAM_HOST=0` / `STREAM_CONTROLLER=1`。

| H4 type | Drf | Stream |
|---|---|---|
| Command 0x01 | `1` | HOST (0) |
| Event 0x04 | `8` | CONTROLLER (1) |
| ACL 0x02 | `2` | DOWN→HOST(0) / UP→CONTROLLER(1) |
| SCO 0x03 | `4` | DOWN→HOST(0) / UP→CONTROLLER(1) |
| ISO 0x05 | — | **默认 personality 无 ISO Drf → WPS 不可表达** |

**ISO 限制**：WPS 默认 personality 的 Drf 只有 Command/ACL/SCO/Event 四类，没有 ISO。v1.1 WPS 后端遇到 ISO 帧 **跳过 + 每会话 warn 一次**（不报错）；Ellisys 后端正常注入 ISO。自定义 personality 扩 ISO 属 NON-Goal。

## 5. 接口定义

### 5.1 SnifferBackend ABC（`backend.py`）

```python
from abc import ABC, abstractmethod
from datetime import datetime
from pybluehost.core.trace import Direction

class SnifferBackend(ABC):
    @abstractmethod
    async def start(self) -> None:
        """启动/连接分析仪软件，完成最小 setup（一次性，可慢/阻塞）。"""

    @abstractmethod
    async def inject(
        self, h4_type: int, direction: Direction, payload: bytes, wall_clock: datetime
    ) -> None:
        """注入单个 HCI 包（payload 不含 H4 type 字节）。需非阻塞事件循环。"""

    @abstractmethod
    async def stop(self) -> None:
        """收尾：停录制 / 释放 socket / 卸载 DLL（幂等）。"""
```

### 5.2 VirtualSnifferSink（`sink.py`）

```python
_HCI_LAYER = "hci"

class VirtualSnifferSink:
    def __init__(self, backend: SnifferBackend) -> None:
        self._backend = backend

    async def on_trace(self, event: TraceEvent) -> None:
        if event.source_layer != _HCI_LAYER:
            return
        raw = event.raw_bytes
        if len(raw) < 1:
            return
        h4_type = raw[0]
        payload = raw[1:]
        await self._backend.inject(h4_type, event.direction, payload, event.wall_clock)

    async def flush(self) -> None:
        pass  # 注入是 fire-and-forget，无缓冲文件

    async def close(self) -> None:
        await self._backend.stop()
```

### 5.3 工厂（`sink.py`）

CLI / 编程接口都用它，**在 `Stack._build` 前调**（这样能捕获 HCI init 序列）：

```python
async def build_virtual_sniffer_sink(spec: "SnifferSpec") -> VirtualSnifferSink:
    backend = _make_backend(spec)   # ellisys / wps；非 Windows → SnifferUnavailableError
    await backend.start()           # 启动分析仪 + 最小 setup（慢，阻塞部分走 executor）
    return VirtualSnifferSink(backend)
```

### 5.4 SnifferSpec（`cli/_sniffer_arg.py`）

```python
@dataclass(frozen=True)
class SnifferSpec:
    backend: str               # "ellisys" | "wps"
    options: dict[str, str]    # tcp/udp/ellisys-path/wps-path 等
```

解析 `ellisys:tcp=46148,udp=24352` / `wps:wps-path=C:\...`；未知 backend 或非法 key → `argparse` error。

### 5.5 Ellisys 纯函数（`ellisys.py`，移植 demo）

```python
def ellisys_packet_type(h4_type: int, direction: Direction) -> int: ...   # §3.2 表

def encode_ellisys_injection_packet(
    wall_clock: datetime, bit_rate: float, packet_type: int,
    hci_payload: bytes, controller_index: int = 0,
) -> bytes: ...   # 沿用 demo prepare_ellisys_hci_injection_packet 字节布局
```

### 5.6 WPS 纯函数（`wps.py`）

```python
def wps_frame_params(h4_type: int, direction: Direction) -> tuple[int, int] | None:
    """→ (drf, stream)；ISO 返回 None（不可表达，调用方跳过）。"""
```

## 6. 后端实现要点

### 6.1 EllisysBackend（V.2）

- `start()`：
  1. 若 analyzer 未运行 → 启动 `Ellisys.BluetoothAnalyzer.exe /remote_control_port=<tcp> /injection_api_port=<udp> /suffix=PTS`
  2. `wait_for_tcp_port`（沿用 demo，最长 60s）
  3. 跑 PowerShell .ps1 加载 `Ice.dll` + `EllisysAnalyzerBluetoothRemoteControlPlugin.dll`，调 `SelectDataSource('injection')` + `StartRecording()`（沿用 demo 序列 + IsRecording 校验）
  4. 创建 UDP socket（`AF_INET, SOCK_DGRAM`）
- `inject()`：`encode_ellisys_injection_packet(...)` → `socket.sendto(pkt, (host, udp_port))`。UDP fire-and-forget，<1ms，直接发不阻塞事件循环（必要时 `sock.setblocking(False)`）。
- `stop()`：可选停录制（沿用 demo `stop_ellisys_recording`，但 PRD 说不做 save trace → 仅关 socket）；幂等。
- PowerShell 启动是一次性 subprocess（demo 已验证），不在每帧路径。

### 6.2 WpsBackend（V.3）

- `start()`：
  1. 启动 `Fts.exe /ComProbe Protocol Analysis System=Generic /oemkey=Virtual`
  2. `ctypes.CDLL(LiveImportAPI.dll)`，配 `InitializeLiveImportEx` / `SendFrame3` / `SendNotification` / `IsAppReady` 签名（沿用 demo `_configure_signatures`）
  3. `InitializeLiveImportEx(connection_string, config_string, &success, mode)` — connection string 用**产品根目录** `liveimport.ini [General]`，config 用**开发包** `[Configuration]`（demo 实测必需组合）
  4. `SendNotification(E_START_CAPTURE_TO_FILE=6)` 启动 capture
- `inject()`：
  - `params = wps_frame_params(h4_type, direction)`；`None`（ISO）→ 跳过 + warn 一次
  - `(drf, stream) = params`；`ts = int(wall_clock.timestamp() * 1e9)`
  - `SendFrame3(len, buf, drf, stream, ts)` —— ctypes 调用可能短暂阻塞 → `await loop.run_in_executor(None, ...)`
- `stop()`：停 capture + 释放 DLL 引用（幂等）。

### 6.3 非阻塞策略

`TraceSystem._dispatch_loop` 是单消费者，串行 `await sink.on_trace`。
- Ellisys：UDP send 极快，直接发。
- WPS：`SendFrame3` 走 `run_in_executor` 防阻塞事件循环。
- v1.1 不引入额外内部队列（TraceSystem 已有 `asyncio.Queue` 缓冲）。若实测高频丢帧再加 backend 内部队列 + 专用 worker（记到风险）。

## 7. CLI 集成（V.4）

`add_trace_arguments` 增：

```python
parser.add_argument(
    "--virtual-sniffer", metavar="BACKEND[:opts]",
    help="Inject live HCI into an analyzer UI: ellisys|wps[:tcp=,udp=,wps-path=,...]",
)
```

`run_app_command` 流程（关键：sink 在 `Stack._build` **之前** 构建好，才能抓 init HCI）：

```python
config = StackConfig()
if hci_log: config.trace_sinks.append(CallbackSink(_print_hci_trace))
if btsnoop is not None: config.trace_sinks.append(BtsnoopSink(btsnoop))
if virtual_sniffer is not None:
    spec = parse_sniffer_arg(virtual_sniffer)          # _sniffer_arg.py
    sink = await build_virtual_sniffer_sink(spec)      # 启动分析仪 + setup
    config.trace_sinks.append(sink)
stack = await Stack._build(transport=transport, config=config)
```

用法：`pybluehost app ble-scan -t usb --virtual-sniffer=ellisys`、`... --virtual-sniffer=wps`。
可与 `--btsnoop` / `--hci-log` 同开，互不影响（各自独立 sink）。

## 8. 错误处理

| 场景 | 行为 |
|---|---|
| 非 Windows 平台 | `_make_backend` 立刻 raise `SnifferUnavailableError("virtual sniffer requires Windows + Ellisys/WPS software")`；CLI 捕获 → exit 1 + 清晰信息 |
| 分析仪软件未装 / exe 路径找不到 | `start()` raise `SnifferError`，提示缺哪个软件 + 可用 `--virtual-sniffer=ellisys:ellisys-path=...` 指定 |
| Ellisys TCP 端口等待超时 | `start()` raise，提示端口被占/版本不符 |
| WPS `InitializeLiveImportEx` 失败 (HRESULT<0) | `check_hresult` raise `SnifferError`（含 HRESULT），提示 connection string/config 组合 |
| 运行中注入失败（UDP send / SendFrame3 偶发） | `inject` 内 try/except，log warning **不**中断协议栈（sniffer 是旁路观测，不能拖垮主流程） |
| ISO 帧 → WPS | 跳过 + warn 一次 |

`SnifferError` / `SnifferUnavailableError` 加到 `pybluehost/core/errors.py`，继承现有错误基类。

## 9. 测试策略

**纯软件可测（CI，跨平台）：**
- 映射表（§3.2/§3.3）逐项断言：8 个 Ellisys 组合 + 8 个 WPS 组合（含 ISO→None）
- `encode_ellisys_injection_packet` 字节布局：固定输入断言完整 hex（对齐 demo）
- `VirtualSnifferSink`：fake backend 记录 `inject` 调用；喂 cmd/event/acl-up/acl-down/sco/iso + 非 hci 层 + 空 payload 事件，断言 filter + 拆 H4 + 参数正确
- Ellisys 后端：bind 真实本地 UDP socket（mock server），`inject` 后断言收到字节（沿用 `test_live_virtual_sniffer.py` 思路，跨平台）
- WPS 后端：fake `ctypes.CDLL`（对象 stub 记录 `SendFrame3` 实参），断言 drf/stream/ts/len 正确；HRESULT 失败路径
- 非 Windows guard：`sys.platform != "win32"` 时构造 backend → 断言 raise
- CLI spec 解析：合法/非法 spec

**真机手动验收（Windows + 真分析仪，记到 `docs/`）：**
- `pybluehost app ble-scan -t usb --virtual-sniffer=ellisys` → Ellisys HCI Injection Overview 实时显示 scan 的 Command/Event/ACL
- 同上 `=wps` → WPS frames analyzed 实时增长
- GATT/SDP 长场景全程不丢帧（计数比对）
- 与 `--btsnoop` 同开两者都正常

**验收门槛**：纯软件测试全绿 + coverage 不低于现行门槛（`--cov-fail-under` 当前 85）。

## 11. 设计自检（spec self-review）

- **占位扫描**：无 TBD；映射值全部来自已读源码常量。
- **一致性**：`SnifferBackend.inject` 签名在 §5.1 定义，§5.2 sink、§6 两后端、§9 测试引用一致（`h4_type, direction, payload, wall_clock`）。
- **方向语义**：统一用 `Direction.DOWN=host→ctrl / UP=ctrl→host`，映射表与 `trace.py:14` 一致。
- **范围**：单一子系统（一个 sink + 两后端 + 一个 CLI flag），适合一份 plan 文档拆 4 个 Task-Plan。
- **歧义**：ISO 在 WPS 不可表达——已明确"跳过 + warn"，非报错。
- **PRD 覆盖**：注入范围 Command/Event/ACL/SCO（+ISO，Ellisys）✅；Windows-only 报错 ✅；CLI flag ✅；不做 save trace ✅；纯软件可测 + 真机手动验收 ✅。
