# PRD v2.0 Design Spec — Classic Audio Profiles

**版本**：design v0.1
**日期**：2026-05-27
**配套 PRD**：[`docs/PRD-v2.0.md`](../../PRD-v2.0.md)
**前置版本**：PRD v1.0 已完成 31 个 Plan，BLE 全栈 + Classic baseband 已就位

## 1. 目标摘要

补齐 Bluetooth Classic 音频协议栈：A2DP（音乐流）+ AVRCP（远程控制）+ HFP/HSP（含 SCO file loopback，不含实时 OS 音频）。所有 profile 双角色（source/sink、controller/target、AG/HF、AG/HS）。Codec 模块独立可用：SBC + CVSD + mSBC 纯 Python（**AAC 推 v2.x 单独子项目**）。

工作量估计：**14-17 周（6 个 Plan）**。每个 Plan 是垂直切片，落地都给用户可见的 milestone。

| v1.0 接口 | v2.0 使用方式 |

## 3. 组件 / Plan 分解（6 个 vertical slice）

### Plan A.1 — Codec 基础模块（无蓝牙依赖）

**目标**：把 SBC、CVSD、mSBC encoder + decoder 做成独立 Python 模块，能用 ETSI test vectors 单元验证。AAC 不在 v2.0 范围（推 v2.x 单独子项目）。

**文件**：
- `pybluehost/audio/codec/__init__.py`
- `pybluehost/audio/codec/sbc.py`（~500 行）
- `pybluehost/audio/codec/cvsd.py`（~120 行 delta modulation）
- `pybluehost/audio/codec/msbc.py`（~80 行，SBC 配置）
- `pybluehost/audio/codec/_common.py`（bit packing、CRC）
- `tests/unit/audio/codec/test_sbc.py`（含 ETSI vector）
- `tests/unit/audio/codec/test_cvsd.py`
- `tests/unit/audio/codec/test_msbc.py`

**公开 API**：

```python
from pybluehost.audio.codec import SBCEncoder, SBCDecoder, CVSDEncoder, CVSDDecoder

# A2DP SBC: stereo 16-bit PCM @ 44.1 kHz → frame bytes
enc = SBCEncoder(sample_rate=44100, channels=2, channel_mode='stereo',
                 blocks=16, subbands=8, allocation='loudness', bitpool=53)
sbc_frame = enc.encode(pcm_bytes)  # frame_size depends on bitpool

dec = SBCDecoder()
pcm_bytes = dec.decode(sbc_frame)  # auto-detect codec params from frame header

# HFP CVSD: 8 kHz mono → SCO packet payload bytes
cvsd_enc = CVSDEncoder()
sco_payload = cvsd_enc.encode(pcm_bytes)
```

**验收**：
- SBC encode ETSI test vector → byte-exact match
- SBC encode/decode round-trip：mean PSNR > 30 dB on test signal
- CVSD encode/decode round-trip：PSNR > 25 dB
- 30+ 单元测试 PASS

**估计**：~2 周

### Plan A.2 — A2DP + AVDTP + SBC 集成

**目标**：第一个端到端 demo——能跑 `Stack.virtual() → A2DPSource ─AVDTP→ A2DPSink → 解码 SBC` 在内存里完成 round-trip。真硬件能跟蓝牙音箱建联 + 推 SBC 流。

**文件**：

- `pybluehost/profiles/classic/a2dp_source.yaml` + `a2dp_sink.yaml`（SDP records）
- `pybluehost/hci/virtual_classic_link.py` 扩展（透传 AVDTP signaling）
- `tests/unit/avdtp/test_*.py`
- `tests/unit/profiles/classic/test_a2dp.py`
- `tests/e2e/test_a2dp_lifecycle.py`

**关键接口**：

```python

from pybluehost.audio.codec import SBCEncoder

src = A2DPSource(stack, supported_codecs=['SBC'])
await stack.register_profile(src)
# 现在 SDP 里有 A2DP Source record; AVDTP discoverable

# 主动 connect to peer

for chunk in pcm_chunks:
    await session.send_pcm(chunk)  # 内部自动 SBC encode + AVDTP framing
```

**Plan 内分 Task**：
- T1: AVDTP signaling (DISCOVER/GET_CAPS/SET_CONFIG/OPEN/START/SUSPEND/CLOSE)

## 4. 关键数据流

### 4.1 A2DP Source 端流程（PyBlueHost 当手机推送音乐）

```
User CLI:  pybluehost app a2dp-source music.wav --target=AA:BB:CC:DD:EE:FF

  1. Stack startup
     └─ register A2DPSource profile
        └─ SDP record (UUID 0x110A) installed
     └─ Open L2CAP signaling channel to peer

  2. AVDTP signaling
     HF→AG ─ DISCOVER ────────────►
              ◄──────────── seid_list, capabilities
     HF→AG ─ GET_CAPABILITIES(seid_X) ──►
              ◄──────────── SBC capability (sample_rates, channel_modes, bitpool range)
     HF→AG ─ SET_CONFIGURATION(seid_X, codec=SBC, params=...) ──►
              ◄──────────── OK
     HF→AG ─ OPEN(seid_X) ─────────►
              ◄──────────── OK
            (L2CAP media channel opens at this point, PSM 0x0019 dynamic)
     HF→AG ─ START(seid_X) ────────►
              ◄──────────── OK

  3. Audio streaming (loop)
     for chunk in wav_file.read_chunks(size=128 samples × 16 blocks):
         pcm_bytes = chunk
         sbc_frame = SBCEncoder.encode(pcm_bytes)   # ~100-120 bytes per frame
         media_packet = AVDTPMediaPacket(
             rtp_header=...,
             payload=sbc_frame * N_frames_per_packet,
         )
         await media_channel.send(media_packet.to_bytes())
     (rate-limited to match real-time playback speed)

  4. Shutdown
     HF→AG ─ SUSPEND(seid_X) ──────►
              ◄──────────── OK
     HF→AG ─ CLOSE(seid_X) ────────►
              ◄──────────── OK
            (media channel closes)
```

### 4.2 A2DP Sink 端流程（PyBlueHost 当蓝牙音箱接手机推送）

```
User CLI:  pybluehost app a2dp-sink --output=received.wav

  1. Stack startup
     └─ register A2DPSink profile
     └─ Wait for incoming connection

  2. AVDTP signaling (peer initiates)
     peer→us ─ DISCOVER ─────────► (we respond with our seids)
     peer→us ─ GET_CAPABILITIES ─► (we respond with SBC capability)
     peer→us ─ SET_CONFIGURATION ► (we accept or reject codec config)
     peer→us ─ OPEN ────────────►
     peer→us ─ START ───────────►

  3. Audio streaming (loop)
     for media_packet_bytes in media_channel.recv():
         pkt = AVDTPMediaPacket.from_bytes(media_packet_bytes)
         for sbc_frame in pkt.payload_frames():
             pcm_bytes = SBCDecoder.decode(sbc_frame)
             await self._sink_buffer.write(pcm_bytes)
     (output: WAV file write, or sounddevice playback)
```

### 4.3 AVRCP PASS_THROUGH（PyBlueHost controller 控制手机播放）

```
User CLI:  pybluehost app avrcp-control --target=AA:BB:... --cmd=play

  1. AVCTP session establish (L2CAP PSM 0x0017)
  2. Send PASS_THROUGH message:
     IPID=0 | Pkt_Type=Single | Profile_ID=0x110E (AVRCP)
     [AV/C command]
       Ctype=Control, Subunit=Panel, OpCode=PASS_THROUGH
       Operation_ID=0x44 (PLAY), State=Pressed
  3. Receive PASS_THROUGH response:
       Response=Accepted
  4. (optionally) Send PASS_THROUGH State=Released

  5. Disconnect AVCTP session
```

### 4.4 HFP SLC 建立（PyBlueHost HF 连接手机 AG）

```
User CLI:  pybluehost app hfp-test --role=HF --target=AA:BB:...

  1. SDP discovery for AG service channel
     ─ Find HFP AG record → RFCOMM channel (e.g. 13)

  2. RFCOMM connect to AG channel
     ─ SABM, UA, parameter negotiation, credit-based flow control

  3. Service Level Connection (HFP 1.7 §4.2)
     HF→AG: AT+BRSF=<HF features bitmask>
     AG→HF: +BRSF: <AG features bitmask>
             OK
     HF→AG: AT+BAC=1,2          (codec list: CVSD, mSBC)
     AG→HF: OK
     HF→AG: AT+CIND=?
     AG→HF: +CIND: ("service",(0-1)),("call",(0-1)),...
             OK
     HF→AG: AT+CIND?
     AG→HF: +CIND: 1,0,0,0,3,3,0
             OK
     HF→AG: AT+CMER=3,0,0,1
     AG→HF: OK
     [SLC established — three-way indicator transfer done]

  4. Optional incoming call simulation
     AG→HF: RING
     AG→HF: +CLIP: "+8613800138000",129
     [HF can answer/reject via ATA / AT+CHUP]

  5. SCO link setup + data path (file loopback)
     AG initiates HCI Setup_Synchronous_Connection
       params: codec=mSBC (negotiated via AT+BAC), retransmission_window=...
     → controller emits Synchronous_Connection_Complete on both sides

     Audio loop (until tear-down, no realtime constraint):
       Outbound (HF→AG):
         WAV file ──► read PCM frame (60 samples for mSBC) ──►
         mSBC encode (60 bytes) ──► HCI SCO Data Packet (type 0x03) ──►
         transport.send()
       Inbound (AG→HF):
         transport.recv() ──► HCI SCO Data Packet parse ──►
         mSBC decode ──► append PCM to output WAV file

  6. Tear down
     HCI Disconnect on SCO handle
     HF: RFCOMM disconnect
```

## 5. 错误处理

### 5.1 协议层错误

| 错误源 | 处理 |
|---|---|
| AVDTP signaling error (BAD_HEADER_FORMAT / BAD_LENGTH 等 spec error codes) | 返回对应 error response；记录 TraceEvent；状态机停在 IDLE |
| AVDTP timeout (SET_CONFIG 后 X 秒未 OPEN) | 内部 timer abort，发 ABORT 给对端，资源回收 |
| AVCTP packet malformed | 丢弃 + log warning |
| AVRCP unsupported PASS_THROUGH opcode | 返回 Response=Not_Implemented |
| HFP unsupported AT command | 返回 ERROR；HF/AG 状态机记录 unknown command 但不中断 SLC |
| HFP AT command malformed (no CRLF, bad syntax) | parser 抛 ATParseError；上层 log + send ERROR |
| RFCOMM disconnect during SLC | profile state machine 转回 IDLE，profile object emit `disconnected` event |

### 5.2 Codec 错误

| 错误源 | 处理 |
|---|---|
| SBC decode 收到 invalid frame header | 抛 `SBCDecodeError`；上层 log + drop packet（不中断流） |
| SBC encode 收到非法 PCM 参数（错误采样率/通道数） | 抛 `ValueError` 立即；调用方应在协商前 validate |
| CVSD/mSBC 同样 pattern |  |
| 对端 A2DP 要求 AAC（v2.0 不支持） | A2DP capability response 不宣告 AAC；如对端只接受 AAC（罕见），协商失败，CLI 报清晰错误 |

### 5.3 OS 音频设备错误（仅 CLI 路径）

| 错误源 | 处理 |
|---|---|
| sounddevice 未装但传了 `--play` | CLI 启动时检测，friendly error："audio extras not installed, use `pip install pybluehost[audio]` or `--play=<file>`" |
| sounddevice 找不到默认输出设备 | CLI exit code 4 + 提示用户用 `--device=<index>` 显式选择 |
| sounddevice 缓冲 underrun | log warning，继续；持续 underrun >5s 时 CLI exit |

### 5.4 真硬件互通错误

| 错误源 | 处理 |
|---|---|
| 对端拒绝 codec capabilities | profile 自动 fallback 到 mandatory codec (SBC for A2DP, CVSD for HFP)；如对端连 mandatory 都拒绝则 abort |
| 适配器不支持 SCO over HCI（HFP 真硬件测试时）| HFP 协议层完成 SLC 后 SCO setup 报 error 0x12 / 收不到 SCO Data Packet。profile log warning，CLI 提示用户："SCO data path 需 USB Alt Setting 切换 (Intel) 或 vendor 命令 (Realtek)，留 v2.1 适配 (see CLASSIC_AUDIO_E2E.md)"。v2.0 在 virtual transport 上保证 e2e 通；真硬件 SCO loopback 收效视适配器 quirk 而定。 |
| 蓝牙耳机短时间多次 reconnect | A2DP profile state machine 接收 OPEN 时如果已有 active session，拒绝并 log；上层应用决定重置 |

## 12. 关于 HFP/HSP "无 OS 音频"边界的精确定义

避免后续歧义，明确 v2.0 vs v2.1 边界：

### 12.1 v2.0 做（含 SCO file loopback）

**协议 + SLC**：
- AT command 完整解析 + 双向交互（HF↔AG 完整 SLC 流程）
- 通话状态机（idle/incoming/outgoing/active/held）
- 通话事件（RING / +CLIP / +CCWA / +CIEV）
- AT+BAC codec list 协商（CVSD / mSBC 都在 list 里）

**SCO link + data path**：
- HCI `Setup_Synchronous_Connection` 命令发出 + 等 `Synchronous_Connection_Complete` 事件
- HCI SCO Data Packet (HCI packet type 0x03) 的打包/解包（v1.0 没做）
- CVSD/mSBC 编解码（codec module Plan A.1 已做）
- VirtualClassicLink 桥接 SCO Data Packet（v1.0 只桥 ACL）

**File-based loopback**（v2.0 SCO 验证手段）：
- Outbound：循环读 WAV 文件 → CVSD/mSBC encode → HCI SCO Data Packet → 送对端
- Inbound：收 HCI SCO Data Packet → 解码 → 写 WAV 文件（追加）
- 不需要实时性（worker 跑得比 wall-clock 快/慢都行）
- CLI：`hfp-test --sco-in=<input.wav> --sco-out=<output.wav>`

**保证**：v2.0 SCO loopback 在 **virtual transport 上端到端验证**（VirtualClassicLink 桥接，没 USB quirk）。真硬件上视适配器是否需要 quirk 适配而定（见 §12.3）。

### 12.2 v2.0 不做（推到 v2.1 或更后）

| 项目 | 原因 |
|---|---|
| 实时麦克风采集 → 编码 → SCO | 需要跨平台 OS 音频后端 + 实时性能调优 |
| 实时 SCO → 解码 → 扬声器播放 | 同上 |
| 跨平台音频后端适配（WASAPI / PulseAudio / CoreAudio） | 各 OS API 差异 + latency 调优 |
| SCO over HCI 适配器 quirk 适配 | 见 §12.3，工作量大 |
| Intel BE200 SCO 切 USB Alt Setting | quirk 的一部分 |
| Realtek vendor HCI 命令切 SCO routing | quirk 的一部分 |
| 多 SCO 并发 / 多通话路 | spec corner case，少见 |

### 12.3 为什么 SCO over HCI 适配器 quirk 不在 v2.0

蓝牙 USB 芯片对 SCO 数据有 3 种 routing：

```
        Bluetooth Chip
         /    |    \
        v     v     v
    HCI bus  PCM/I2S  USB Isoch (Alt Setting)
    (Host)   (codec   (现代 USB 蓝牙)
             chip)
```

**PyBlueHost 是 host 软件栈，必须走 SCO over HCI**。但 SCO over HCI 默认不开启——每家厂商有自己的开启方式：

| 厂商 | 开启方式 |
|---|---|
| Intel | USB Alt Setting 切换：Alt 0=off，Alt 1=CVSD，Alt 6=mSBC wide-band。HCI Setup_Synchronous_Connection 前必须 `usb_set_interface()` 切对应 Alt。不同芯片代号/固件版本 Alt 编号不一样。 |
| Realtek | 默认 SCO 走 PCM 总线。要走 HCI 必须先发 vendor 命令 `HCI_VENDOR_RTK_SET_SCO_ROUTING_TYPE` (opcode 0xFC8B, param 0x02)。 |
| Broadcom | 类似 Intel 但 Alt 编号映射不同。 |
| CSR / Qualcomm | CSR8510 等 BT 4.0 dongle 不支持 SCO over HCI——SCO 必须走 PCM 总线，廉价 dongle 上没接出来直接不通。 |
| Apple / 移动定制 | 专有 HCI 命令，文档未公开。 |

**Linux BlueZ 处理这块从 2010 年到现在还在改 bug**——bugzilla 至今有 case。这套 quirk 适配 PyBlueHost v2.0 不做。

### 12.4 Windows 没有特权路径

Windows 用户用微软自家蓝牙打电话听到声音——是因为 `bthusb.sys` 内核驱动**自动**做了上述所有 quirk 适配（切 Alt Setting、发 Realtek vendor 命令），然后通过 `BthAudioSvc` 把 SCO PCM 喂给 WASAPI。

**但 PyBlueHost 用 Zadig 把适配器换成 WinUSB 后，微软那套全 bypass 掉了**。PyBlueHost 自己负责所有 quirk 适配。所以：

| | 微软默认 bthusb.sys | PyBlueHost (WinUSB) |
|---|---|---|
| 切 Alt Setting | 内核驱动自动 | 我们自己（v2.1）|
| Realtek vendor HCI 命令 | 内核驱动自动 | 我们自己（v2.1）|
| SCO PCM 接 OS 音频 | BthAudioSvc 做 | 我们自己（v2.1）|

**结论**：Windows 跟 Linux 在 PyBlueHost (WinUSB) 模式下面临**完全相同的 SCO quirk 问题**。Windows 没有 free pass。

### 12.5 v2.0 / v2.1 SCO loopback 在真硬件上的预期

| 适配器 | virtual transport | v2.0 hardware | v2.1 Plan B.1 hardware |
|---|---|---|---|
| 任意（virtual） | ✓ 端到端工作 | n/a | n/a |
