- 如果 `tests\unit\pts` 失败，先修复 IUT controller 或 PTS action 层，不要继续跑需要 MMI action 的 PTS case。

## 4. 清理旧进程

执行前先关闭旧的 PTS automation 进程和旧 controller，避免 dongle 被占用或 controller 仍在跑旧代码。

```powershell
Get-CimInstance Win32_Process |
  Where-Object {
    $_.Name -eq 'PTS.exe' -and $_.CommandLine -match 'autotest|-Embedding'
  } |
  ForEach-Object {
    Stop-Process -Id $_.ProcessId -Force
  }

Get-CimInstance Win32_Process |
  Where-Object {
    $_.CommandLine -match 'pts_iut_controller|18766' -and $_.Name -ne 'powershell.exe'
  } |
  ForEach-Object {
    Stop-Process -Id $_.ProcessId -Force
  }
```

## 5. 启动 IUT JSON Controller

启动 controller：

```powershell
cd H:\github\bluetooth\pybluehost

$stamp = Get-Date -Format 'yyyyMMdd_HHmmss'
$logDir = Join-Path (Get-Location) "runs\pts_iut_controller_$stamp"
New-Item -ItemType Directory -Path $logDir -Force | Out-Null

$outLog = Join-Path $logDir 'controller.out.log'
$errLog = Join-Path $logDir 'controller.err.log'

Start-Process `
  -FilePath 'uv' `
  -ArgumentList @(
    'run',
    'python',
    'scripts\pts_iut_controller.py',
    'usb:0A12:0001#1',
    '--port',
    '18766',
    '--log-level',
    'INFO'
  ) `
  -WorkingDirectory (Get-Location) `
  -RedirectStandardOutput $outLog `
  -RedirectStandardError $errLog `
  -WindowStyle Hidden

Start-Sleep -Seconds 5
Get-Content $outLog -Tail 40
Get-Content $errLog -Tail 40
```

校验 controller：

```powershell
function Send-IutJson {
  param([hashtable]$Payload)

  $client = [System.Net.Sockets.TcpClient]::new('127.0.0.1', 18766)
  try {
    $stream = $client.GetStream()
    $writer = [System.IO.StreamWriter]::new($stream, [System.Text.Encoding]::UTF8, 1024, $true)
    $writer.NewLine = "`n"
    $reader = [System.IO.StreamReader]::new($stream, [System.Text.Encoding]::UTF8, $false, 1024, $true)
    $writer.WriteLine(($Payload | ConvertTo-Json -Compress))
    $writer.Flush()
    $reader.ReadLine()
  }
  finally {
    $client.Dispose()
  }
}

Send-IutJson @{ cmd = 'status' }
Send-IutJson @{ cmd = 'connectable'; enabled = $true }
Send-IutJson @{ cmd = 'discoverable'; enabled = $true }
```

预期 `status` 返回类似：

```json
{"ok":true,"bd_addr":"00:1A:7D:DA:71:11","transport":"usb:0A12:0001#1"}
```

## 6. 选择 PTS Dongle

如果用 PTS GUI 手动跑，先在 PTS GUI 中确认 Intel dongle 可用。如果用 COM automation，可用以下流程确认 PTS 使用 Intel BE200：

```powershell
$pts = New-Object -ComObject 'ProfileTuningSuite_6.PTSControlServer'
$pts.SelectDevice('')
Start-Sleep -Seconds 6

$rawDevices = [string]$pts.GetDeviceList()
$rawDevices

$devices = $rawDevices -split '[\s,;]+' | Where-Object { $_ }
$device = $devices | Where-Object { $_ -like 'USB_INTEL:Free:*' } | Select-Object -First 1

if (-not $device) {
  throw "No free Intel PTS dongle found. Raw device list: $rawDevices"
}

$pts.SelectDevice($device)
Start-Sleep -Seconds 8
$pts.GetPTSBluetoothAddress()
```

预期地址：

```text
C88A9A6D5F5F
```

如果 `GetPTSBluetoothAddress()` 抛 `0x849C0043`，通常是 stale `PTS.exe autotest -Embedding` 占用 dongle。按第 4 节清理后重试。

## 11. 常见问题

### PTS dongle 无法获取地址

现象：

```text
GetPTSBluetoothAddress() 返回 0x849C0043
```

处理：

1. 关闭 PTS GUI。
2. 按第 4 节清理 stale `PTS.exe autotest -Embedding`。
3. 重新选择 `USB_INTEL:Free:*` dongle。

### SDP 找不到 UUID 0x0100 record

现象：

```text
No Service Record Handle has been found using UUID(0x0100)
```

处理：

1. 停止旧 controller。
2. 重新启动 `scripts\pts_iut_controller.py`。
3. 确认 controller 启动日志中没有 SDP record 注册错误。

### SDP invalid request 没有返回预期 error code

处理：

1. 先跑 `uv run pytest tests\unit\classic\test_sdp.py -q`。
2. 确认 controller 已重启。
3. 查看 PTS XML 中 expected/received PDU。

参考期望：

| 场景 | 期望 SDP error |
|---|---|
| invalid handle | `0x0002` |
| invalid request syntax | `0x0003` |
| invalid PDU size | `0x0004` |

### L2CAP case 超时或 INDCSV

现象：

```text
PTS 提示 Please send L2CAP Connection REQ to PTS 后超时
```

处理：

1. 确认 controller `status` 正常。
2. 确认 IUT connectable/discoverable 已开启。
3. 在 MMI 提示出现后执行第 8 节 `l2cap-connect` 命令。
